# 实时预测开发安排

## 共享预测核心

从现有桌面工具的 `d36_predictor_core.py` 及研究特征构造程序整理统一入口。桌面端和 HTTP 服务调用同一套输入检查、单位转换、缺测处理和概率输出。

输入使用明确字段。主量氧化物以质量百分数表示，微量元素以 ppm 表示，同位素以比值表示。区分元素 Pb 浓度与三个 Pb 同位素比值。缺测用空值表示，避免与零值混淆。

预测结果包含样品标识、九类概率、预测类别、输入覆盖、采用的模型版本与所用参考集版本。为完整和缺测样品分别检查效果，混合参考集的完整样品损失及缺测样品收益保留在版本验收中。

## 软件和网站

1. 固定一个可运行的模型与参考集版本，记录字段顺序、权重哈希和依赖。
2. 提供共享的 Python 单样品及批量预测接口，接入现有桌面界面。
3. 建立 HTTP 服务，分别提供健康状态、模型信息、单样品及文件批量预测。
4. 网站提供中文字段表单、CSV/XLSX 上传、缺测提示及结果下载。
5. 测量实际推理延时和显存占用，再决定在线采用 LightGBM、LimiX-2M 或分条件调用。

## 发布前验收

- 相同输入在软件和网站得到相同概率。
- CSV 与 XLSX 字段、单位和缺测解释一致。
- 输出概率有限且每行合计为 1，错误输入返回明确字段信息。
- 检查单样品延迟、批量吞吐、并发请求及重试。
- 按完整和缺测测试子集分别记录模型表现。

网站、HTTP 接口和 LimiX-2M 在线推理服务将在上述基础上开发。
